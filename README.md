# قالب CRM فروش — راهنمای نصب و اجرا

این یک نرم‌افزار داخلی (لوکال) است؛ روی یک سیستم/سرور در محل شما اجرا می‌شود و بقیه سیستم‌های همان شبکه می‌توانند از طریق مرورگر به آن وصل شوند. هیچ داده‌ای به بیرون از شبکه شما ارسال نمی‌شود.

## ۱. پیش‌نیاز

نصب Node.js (نسخه ۱۸ به بالا) روی سیستمی که قرار است به‌عنوان سرور استفاده شود:
https://nodejs.org (نسخه LTS را دانلود و نصب کنید)

## ۲. نصب

پوشه `auto-crm-app` را روی سرور کپی کنید، سپس در همان پوشه:

```
npm install
```

این دستور فقط یک‌بار لازم است (و فقط زمانی که فایل‌های پروژه تغییر کنند).

## ۳. تنظیمات (فایل `.env`)

تنظیمات محیطی برنامه (پورت، کلید نشست و…) در فایل `.env` کنار فایل‌های پروژه نگهداری می‌شود. این فایل مقادیر حساس دارد و عمداً در Git ذخیره نمی‌شود.

برای راه‌اندازی روی یک سیستم جدید، از روی نمونه یک کپی بسازید و مقادیرش را پر کنید:

```
copy .env.example .env      (در ویندوز)
cp .env.example .env        (در لینوکس/مک)
```

| متغیر | معنی | پیش‌فرض |
|---|---|---|
| `PORT` | پورتی که سرور روی آن گوش می‌دهد | `3000` |
| `HOST` | آدرس گوش‌دادن؛ `0.0.0.0` یعنی از کل شبکه در دسترس است | `0.0.0.0` |
| `SESSION_SECRET` | کلید رمزنگاری نشست کاربران (یک رشته تصادفی و مخفی) | ساخت خودکار |
| `SESSION_MAX_AGE_DAYS` | مدت اعتبار ورود کاربر، به روز | `30` |
| `NODE_ENV` | روی سرور واقعی `production` بگذارید؛ نوع امن کوکی از HTTP/HTTPS خودکار تشخیص داده می‌شود | — |
| `LOGIN_RATE_WINDOW_MINUTES` | بازه‌ی شمارش تلاش‌های ناموفق ورود، به دقیقه | `15` |
| `LOGIN_RATE_MAX_ATTEMPTS` | سقف تلاش ناموفق ورود در آن بازه | `10` |
| `DATABASE_URL` | آدرس اتصال به دیتابیس انتخاب‌شده | — |
| `DB_CONNECTION_LIMIT` | اندازه استخر اتصال MySQL | `10` |

برای ساختن یک `SESSION_SECRET` امن:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## ۴. اجرا

```
npm start
```

در کنسول پیامی مشابه زیر نمایش داده می‌شود:

```
دسترسی از همین سیستم : http://localhost:3000
دسترسی از سایر سیستم‌های شبکه : http://<آی‌پی این سیستم>:3000
```

## ۵. ورود اولیه

در **اولین اجرا** یک حساب مدیر پیش‌فرض به‌صورت خودکار ساخته می‌شود و مشخصات آن هم در کنسول و هم در فایل `SETUP.txt` (کنار فایل‌های پروژه) نوشته می‌شود:

- نام کاربری: `admin`
- رمز عبور: یک رمز تصادفی (در `SETUP.txt` ببینید)

با این حساب وارد شوید، از تب «کاربران» برای هر کارشناس فروش و هر مدیر دیگر یک حساب جداگانه بسازید، و حتماً رمز عبور حساب admin را از منوی «تغییر رمز عبور» عوض کنید. فایل `SETUP.txt` را پس از تغییر رمز حذف کنید.

## ۶. دسترسی از سایر سیستم‌های شبکه

سرور به‌صورت پیش‌فرض روی همه شبکه‌های سیستم گوش می‌دهد، پس کافی است آی‌پی سیستم سرور را پیدا کنید:

- ویندوز: در Command Prompt دستور `ipconfig` را بزنید و مقابل «IPv4 Address» را ببینید.
- لینوکس/مک: دستور `ip addr` یا `ifconfig` را بزنید.

سپس از هر سیستم دیگر در همان شبکه (Wi-Fi یا LAN)، در مرورگر آدرس زیر را باز کنید:

```
http://<آی‌پی سرور>:3000
```

اگر فایروال ویندوز یا لینوکس پورت ۳۰۰۰ را مسدود کرده، باید یک قانون Inbound برای پورت TCP 3000 اضافه کنید تا سایر سیستم‌ها بتوانند وصل شوند.

می‌توانید پورت را هم تغییر دهید، مثلاً:

```
PORT=8080 npm start
```

## ۷. اجرای دائمی (اختیاری)

اگر می‌خواهید سرور بعد از بستن ترمینال هم روشن بماند و در صورت ری‌استارت سرور به‌طور خودکار بالا بیاید، می‌توانید از ابزار PM2 استفاده کنید:

```
npm install -g pm2
pm2 start server.js --name auto-crm
pm2 save
pm2 startup
```

## ۸. پشتیبان‌گیری از داده‌ها

پشتیبان‌گیری خودکار است و نیازی به کار دستی ندارد.
توضیح کامل در بخش «پشتیبان‌گیری از داده‌ها» در ادامه‌ی همین فایل آمده است.

## ۹. دیتابیس: MariaDB

لپ‌تاپ و سرور هر دو MariaDB 10.11 دارند (Postgres از ۱۴۰۵/۰۸/۲۰ کنار گذاشته شد).
روی لپ‌تاپ: `powershell -File scripts\start-local-db.ps1` (پورت 3307). در `.env`:

```env
DATABASE_URL=mysql://root:@127.0.0.1:3307/crm_template
```

ساختار جدول‌ها: `prisma/mysql/schema.prisma`؛ ساخت یا به‌روزرسانی جدول‌ها:

```bash
npm run db:generate
npm run db:migrate
```

## امنیت و نشست کاربران

- **نشست‌ها در دیتابیس ذخیره می‌شوند** (جدول `session`)، نه در حافظه‌ی سرور. یعنی با ری‌استارت شدن سرور، کاربرانی که وارد بودند از سیستم خارج نمی‌شوند. نشست‌های منقضی‌شده هر ۱۵ دقیقه خودکار پاک می‌شوند.
- **کوکی نشست** `httpOnly` است (کد جاوااسکریپت صفحه به آن دسترسی ندارد) و `sameSite=lax`. ویژگی `secure` بر اساس پروتکل واقعی درخواست تنظیم می‌شود: روی HTTPS فعال است و روی HTTP غیرفعال، بنابراین ورود در هر دو حالت پس از تازه‌سازی صفحه حفظ می‌شود.
- **محدودسازی تلاش ورود**: بعد از ۱۰ تلاش ناموفق در ۱۵ دقیقه، ورود از آن آی‌پی موقتاً قفل می‌شود. ورودهای موفق شمرده نمی‌شوند، پس کاربر عادی هیچ‌وقت به این محدودیت نمی‌خورد. این مقادیر در `.env` قابل تغییرند.
- **هدرهای امنیتی** با `helmet` فعال است، شامل سیاست محتوا (CSP) که فقط اجازه‌ی بارگذاری فایل‌های خود برنامه و فونت گوگل را می‌دهد.

## پشتیبان‌گیری از داده‌ها

پشتیبان‌گیری **خودکار** است: هر روز ساعت ۱۴:۰۰ یک نسخه‌ی فشرده از کل دیتابیس در
`D:auto-crm-backups` ساخته می‌شود. اگر کامپیوتر آن ساعت خاموش باشد، ویندوز در
اولین فرصت جبران می‌کند.

هر فایل بعد از ساخته شدن **بررسی می‌شود** (باز می‌شود و وجود جدول‌های اصلی چک می‌شود)؛
اگر ناقص باشد پاک می‌شود تا فایل خراب جای نسخه‌ی سالم را نگیرد.

### چه مدت نگه داشته می‌شوند؟

- ۳۰ نسخه‌ی آخر همیشه
- به‌علاوه، اولین نسخه‌ی هر ماه هرگز پاک نمی‌شود (بایگانی ماهانه)

### دستورهای دستی

```
npm run backup              گرفتن پشتیبان همین حالا
npm run backup:schedule     ثبت یا به‌روزرسانی زمان‌بندی خودکار
npm run backup:unschedule   خاموش کردن پشتیبان‌گیری خودکار
```

### بازگرداندن اطلاعات از پشتیبان

اگر روزی لازم شد اطلاعات را برگردانید:

```
node -e "const fs=require('fs'),z=require('zlib');fs.writeFileSync('restore.sql',z.gunzipSync(fs.readFileSync('D:/auto-crm-backups/FILE.sql.gz')))"
```

(به‌جای `FILE` نام فایل پشتیبان را بگذارید.) سپس برای PostgreSQL:

```
psql -U postgres -c "DROP DATABASE crm_template;"
psql -U postgres -c "CREATE DATABASE crm_template ENCODING 'UTF8';"
psql -U postgres -d crm_template -f restore.sql
```

یا برای MySQL:

```bash
mysql -u crm_template -p -e "DROP DATABASE IF EXISTS crm_template; CREATE DATABASE crm_template CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u crm_template -p crm_template < restore.sql
```

> این کار داده‌های فعلی را پاک می‌کند؛ قبلش حتماً یک `npm run backup` بگیرید.

### یک نکته‌ی مهم

پشتیبان‌ها روی **همین کامپیوتر** ذخیره می‌شوند. اگر هارد خراب شود یا کامپیوتر گم شود،
پشتیبان‌ها هم از بین می‌روند. هر چند وقت یک‌بار پوشه‌ی `D:auto-crm-backups` را روی
یک فلش یا فضای ابری کپی کنید.

## شعبه‌ها (چندشعبه‌ای)

- هر کاربر به **یک شعبه** تعلق دارد. انتخاب شعبه هنگام ساخت کاربر اجباری است و بعداً از جدول کاربران قابل تغییر است.
- شعبه‌ی هر سرنخ **خودکار** تعیین می‌شود: شعبه‌ی کارشناسی که سرنخ به‌نام اوست. کاربر شعبه را انتخاب نمی‌کند. وقتی مدیر سرنخی را به‌نام کارشناس دیگری ثبت می‌کند، شعبه‌ی همان کارشناس ثبت می‌شود تا گزارش شعبه‌ها درست بماند.
- مدیر در فهرست سرنخ‌ها و در گزارش‌ها یک انتخابگر «همه شعبه‌ها / یک شعبه» دارد.
- کارشناس همچنان فقط سرنخ‌های خودش را می‌بیند — صرف‌نظر از شعبه. قواعد دسترسی تغییری نکرده‌اند.
- تب «شعبه‌ها» (فقط مدیر): ساخت و ویرایش شعبه. شعبه‌ها حذف نمی‌شوند تا سرنخ‌های گذشته بی‌صاحب نمانند.
- گزارش «مقایسه شعبه‌ها» در تب عملکرد کارشناسان: تعداد سرنخ، سرنخ‌های امروز، موفق، منصرف‌شده و نرخ موفقیت به تفکیک شعبه.

## استقرار روی سرور واقعی

راهنمای کامل و قدم‌به‌قدم بردن برنامه روی یک سرور مجازی اوبونتو (امنیت سرور، Node، PostgreSQL،
PM2، Nginx و HTTPS) در فایل [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) است.

کد روی هیچ سرویس بیرونی قرار نمی‌گیرد؛ مخزن Git روی خودِ سرور شماست.

برای انتشار نسخه‌ی جدید روی سروری که از قبل راه‌اندازی شده:

```
git push server main                          # روی کامپیوتر خودتان
cd ~/crm-template && ./scripts/deploy.sh          # روی سرور
```

## ساختار پوشه‌ها

```
auto-crm-app/
├── server.js          نقطه شروع برنامه؛ Express، نشست‌ها و امنیت
├── api.js             ثبت ماژول‌ها زیر /api/v1
├── modules/
│   ├── core/          ورود، کاربران، شعبه‌ها (زیربنای مشترک)
│   └── crm/           سرنخ‌ها، پیگیری‌ها، گزارش‌های فروش
├── shared/            ابزارهای عمومی: اتصال دیتابیس، اکسل، مدیریت خطا
├── public/            رابط کاربری (HTML، CSS، JavaScript، تصاویر)
├── prisma/            طراحی جدول‌ها و تاریخچه تغییرات دیتابیس
├── scripts/           انتقال داده و انتشار روی سرور
├── deploy/            فایل نمونه Nginx
├── docs/              مستندات (نقشه راه، معماری، استقرار)
├── .env               تنظیمات واقعی (در Git ذخیره نمی‌شود)
└── .env.example       نمونه تنظیمات، بدون مقدار حساس
```

## معماری برنامه

کد ماژولار چیده شده تا ماژول‌های آینده (انبار، حسابداری) بدون دست زدن به CRM فعلی اضافه شوند:

```
مرورگر ──► server.js ──► api.js (/api/v1) ──► modules/… ──► services/… ──► PostgreSQL
```

هیچ فایلی در پوشه‌های `routes/` مستقیماً به دیتابیس دستور نمی‌دهد؛ همه‌ی کوئری‌ها داخل
`services/` هر ماژول هستند.

توضیح کامل معماری، دلیل انتخاب‌های فنی، قوانین دسترسی و راهنمای افزودن ماژول جدید در
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) است.

## ساختار دسترسی‌ها

- **کارشناس فروش**: فقط سرنخ‌هایی را می‌بیند و پیگیری می‌کند که به نام خودش ثبت شده باشد.
- **مدیر**: همه سرنخ‌های همه کارشناسان را می‌بیند، داشبورد مدیریتی و گزارش عملکرد کارشناسان و گزارش تقاضای محصولات ناموجود را در اختیار دارد، و می‌تواند حساب کاربری کارشناسان و مدیران دیگر را بسازد یا غیرفعال کند.

هر کارشناس و هر مدیر با نام کاربری و رمز عبور مخصوص به خودش وارد می‌شود؛ نیازی به انتخاب دستی نام از یک لیست نیست — سیستم هنگام ثبت سرنخ، آن را خودکار به‌نام کاربر واردشده ثبت می‌کند.
